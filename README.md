в домашнем задании по докеру было питон приложение, которое считает http запросы. собственно, его я сделал на 8 баллов, а скрипт на 10 писать не стал. давайте же перейдем к тому что я сделал поэтапно

## 1. собрал невероятный контейнер и даже запустил его

```bash
docker build -t hw3-counter .
docker run -d --name hw3-counter -p 8080:8000 -e 'GREETING=privet iz dockera!' hw3-counter

curl http://127.0.0.1:8080/
curl -X POST http://127.0.0.1:8080/increment
curl http://127.0.0.1:8080/
```

докер! (типа логарифм от докера типа логи):

```text
2026-11-24 12:45:08,332 listening port=8000 storage=sqlite
2026-11-24 12:45:16,230 http 192.168.65.1 "GET / HTTP/1.1" 200 -
2026-11-24 12:45:16,263 http 192.168.65.1 "POST /increment HTTP/1.1" 200 -
```

после get счетчик был 0, post увеличил на 1, еще один get ничего не изменил, потом еще один post увеличил счетчик до 2.

## 2. второй этапище

я настроил запуск приложения через compose. порт и приветствие задаются через app_port и greeting. для хранения данных юзал volume counter_data, дабы счетчик на Руси сохранялся коли контейнер удалят. после того как я выполнил docker compose down и docker compose up -d счетчик остался равным единице, несмотря на пересоздание контейнера, а это круто.

## 3. редис

в итоге настроены два сервиса app и redis. для редис вклбчил запись aof. для обоих сервисов сделал здоровья проверки (healthcheks). данные редиса лежат в volume redis_data, а само приложение ждет пока редис будет готов.

```bash
curl -X POST http://127.0.0.1:8080/increment
curl -X POST http://127.0.0.1:8080/increment

docker compose down
docker compose up -d
curl http://127.0.0.1:8080/
```

после еще двух запросов счетчик стал 3, после пересоздания им и остался, это зачет.

```bash
docker compose stop redis
```

после команды docker compose start redis приложение без перезапуска могло воркать с хранилищем.

## 4. запуск проекта

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
```

для изменения приветствия гринтинг можно редачить в .env , а для изменения порта - app_port.

приложение доступно. для остановки прост docker compose down, все топчик!
